6.4 Como colocar no ar (ainda não feito)

  1. Hostinger: criar o subdomínio (ex.: app.seudominio.com.br), subir e extrair 6-bistro-connect-plataforma.zip na pasta dele, ativar SSL.
  2. Supabase: criar um projeto novo, separado do site oficial (ex.: plataforma). Rodar plataforma/supabase/01-plataforma.sql no SQL Editor.
  3. Authentication: aqui o cadastro fica ligado (os empreendedores se cadastram), com “Confirm email” ligado. Em URL Configuration: Site URL = endereço da plataforma; Redirect URLs = https://app.seudominio.com.br/entrar.html*.
  4. Preencher assets/config.js da plataforma (window.BC): supabaseUrl, supabaseKey (anon), suporteWhatsapp, site.
  5. Criar a sua conta pelo /entrar.html e tornar-se administrador da plataforma no SQL Editor: 
    insert into public.plataforma_admins (user_id)
select id from auth.users where email = 'adilsonrutes@gmail.com';
  6. Testar com 3 a 5 lojas reais antes de divulgar.

8. Segurança: o que protege o sistema

  • Login em 2 etapas obrigatório nos painéis; saída automática após 30 minutos; sessão só na aba aberta.
  • Regras no banco (RLS): visitante só cria lead ou pedido; não lê nada. Só administradores leem leads. Na plataforma, uma loja nunca vê dados de outra.
  • Preço conferido no banco: o total de cada pedido é recalculado com os preços cadastrados. Mudar o preço pelo navegador não adianta.
  • Limites contra robôs: leads por WhatsApp/dia e por 10 minutos; pedidos por telefone.
  • .htaccess: HTTPS obrigatório, bloqueio de arquivos internos (.sql, .md, ferramentas), cabeçalhos de proteção, painel sem indexação no Google.
  • CSP: o navegador só roda os scripts aprovados; script injetado por invasor é bloqueado.

Regras de ouro

  1. Nunca compartilhe a chave service_role/secret, a senha do banco ou print do QR Code do autenticador.
  2. Senha forte (12+ caracteres) e única para cada serviço. Use um gerenciador de senhas.
  3. Ligue o login em 2 etapas também na Hostinger, no Supabase, no GitHub, no e-mail e no Meta Business.
  4. A cada 3 meses: revise quem está em admins e exporte os leads em CSV como cópia.

9. Como fazer atualizações

Existem quatro tipos de atualização. Comece sempre pelo mais simples.

9.1 Conteúdo do dia a dia (sem mexer em arquivos)

Leads, orçamentos, metas, dados da empresa (site oficial) e cardápio, preços, fotos, horários, taxa de entrega, equipe (lojas e plataforma) são mudados pelo painel. A mudança aparece na hora e não precisa de Hostinger.

9.2 Configuração (WhatsApp, Pixel, Supabase)

  1. Hostinger › Gerenciador de Arquivos › public_html/assets/config.js › Editar.
  2. Mude só o valor entre aspas. Não apague vírgulas nem chaves { }.
  3. Salve e abra o site com Ctrl+F5.

9.3 Nova versão do site ou do sistema (arquivos)

Quando houver melhorias (feitas pelo Claude ou por um desenvolvedor), você recebe um zip novo. Siga sempre esta ordem:

  1. Backup antes de tudo: no Gerenciador de Arquivos, selecione o conteúdo de public_html › Compactar › baixe o zip para o seu computador. (Confira também se a Hostinger tem backup automático no seu plano, em hPanel › Backups.)
  2. Guarde o seu config.js: baixe public_html/assets/config.js. Ele tem as suas chaves e o seu WhatsApp, e o zip novo vem com um config.js vazio.
  3. Envie o zip novo para public_html e Extraia, aceitando substituir os arquivos.
  4. Devolva o seu config.js para public_html/assets/ (substituindo o vazio). Se aparecer config1.js, apague o config.js vazio e renomeie o config1.js para config.js.
  5. Apague o zip do servidor.
  6. Abra o site com Ctrl+F5 e faça o teste rápido (seção 9.6).
CuidadoNunca apague a pasta assets/ inteira, o .htaccess ou a pasta admin/ sem ter o backup. Se algo der errado, extraia o zip de backup e tudo volta como estava.

9.4 Mudanças no banco de dados (SQL)

  • Atualizações de banco vêm em arquivos .sql. Rode no Supabase › SQL Editor › New query › colar › Run.
  • Todos os arquivos deste projeto podem ser rodados mais de uma vez sem perder dados.
  • O aviso “destructive operations” é normal quando o arquivo ajusta permissões; leia o que o arquivo diz no topo antes de confirmar.
  • Nunca rode comandos que comecem com drop table ou delete from sem ter certeza e sem exportar os dados antes.
  • Plano gratuito do Supabase não oferece backup para baixar: exporte os leads em CSV pelo painel com frequência. No plano pago, os backups diários ficam em Database › Backups.

Para a pessoa (ou o Claude) entender o projeto sem começar do zero, informe:

Informações técnicas importantes para quem for mexer no código:

  • Proteção CSP: depois de editar qualquer <script> dentro de um HTML, rode python3 ferramentas/csp.py arquivo.html; senão o script deixa de funcionar.
  • Painel das lojas: o original fica em paineis/loja/. Depois de mudar, rode sh ferramentas/montar-paineis.sh (copia para os sites) e python3 ferramentas/montar-painel-plataforma.py (gera o painel da plataforma).
  • Padaria & Café: o código é compilado; as mudanças são feitas pelo ferramentas/padaria-ligar-banco.py a partir de historico/padaria-v17-app-original.js.
  • Cada mudança deve virar um commit com descrição clara no GitHub.

9.6 Teste rápido depois de qualquer atualização

  • Site abre no computador e no celular, com imagens e sem rolar para o lado
  • Botões de WhatsApp abrem com o número certo
  • Formulário de contato: enviar um teste e ver o lead no painel
  • Painel: entrar com e-mail, senha e código; abrir Leads, Orçamentos e gerar um PDF
  • Lojas: fazer um pedido de teste, ver no painel e abrir o link de rastreio
